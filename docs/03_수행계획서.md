# 1. 역할군

강의계획서가 「RnR(Role and Responsibility)에 따라 개발 진행」을 요구하고, 평가에 「각 팀원의 역할 설명 / 협업 능력 / 기여도」가 있으므로 역할군을 먼저 정함.

팀 규모 근거: 강의계획서상 팀장이 팀원 4~5명을 채용함 (1명 면접, 3~4명 무작위) → 팀장 포함 최대 6인.

## 1.1 여섯 자리

| ID | 역할군 | 맡는 요구사항 | 산출물 | 난도 |
|---|---|---|---|---|
| R0 | 팀장·통합 | IF-UI-04, QR-R, DC-05·06, 측정 | `app/`, `domain/`, 발표 | — |
| R1 | 수집 | FR-IN, FR-DEP | `collect/` | 중 |
| R2 | 해석 | FR-LIC, DR-01~03 | `resolve/`, 별칭 사전 | 상 |
| R3 | 판정 | FR-JDG, DR-04·05 | `judge/`, 등급표, 정답셋 | 상 |
| R4 | 조회 | FR-VUL, IF-SW, CR-02·03 | `vuln/`, `adapters/` | 중 |
| R5 | 화면·배포 | FR-OUT, IF-UI, QR-U, CR-01·04, DC-04 | `web/`, `Dockerfile` | 중 |

# 2. 일정

강의 일정은 **마감과 휴강을 파악하는 데만** 씀. 어떤 기법을 언제 쓸지는 정하지 않음 (설계지침 §1).

**기준 시점: 5주차.** 4주차(9/28)에 팀원이 배정됐고, 이번 주(10/2)는 4주차 끝이라 실제 착수는 5주차로 봄.

# 4. 협업 규칙

강의계획서가 Public Repo, Issue, PR, Branch 사용을 요구함. 가산점 항목이기도 함.

## 4.1 브랜치

| 종류 | 이름 | 규칙 |
|---|---|---|
| 기본 | `main` | 보호. 직접 push 금지 |
| 기능 | `feat/<모듈>-<요구사항ID>` | 예: `feat/resolve-FR-LIC-05` |
| 수정 | `fix/<요구사항ID>-<내용>` | |
| 문서 | `docs/<내용>` | |

## 4.2 PR 양식

```markdown
## 무엇을
<한 줄>

## 관련
- 이슈: Closes #12
- 요구사항: FR-LIC-05

## 적용한 강의 요소
- L05 FCF 디자인 패턴 — resolve/strategies.py:30

## 점검
- [ ] 새 ABC를 만들지 않았음
- [ ] domain/ 이 표준 라이브러리 외에는 import 하지 않음
- [ ] 함수 50줄, 파일 300줄 이하
- [ ] 테스트가 네트워크 없이 통과함

## GPT 사용 여부
사용함 / 사용 안 함

## 사용한 프롬프트
<사용했다면 그대로>
```

GPT 사용 여부와 프롬프트 기록은 강의계획서 요구 사항임. 빠뜨리지 않음.

## 4.3 이슈 라벨

| 라벨 | 뜻 |
|---|---|
| `R0`~`R5` | 담당 역할군 |
| `M` / `S` / `C` | SRS 우선순위 |
| `blocked` | 다른 작업 때문에 막힘 |
| `gate-G1` / `gate-G2` | 해당 관문 대상 |

## 4.4 리뷰

- PR은 팀장과 다른 역할군 1명이 승인해야 머지함
- `domain/` 변경은 전원 승인
- 리뷰 없이 머지하지 않음
